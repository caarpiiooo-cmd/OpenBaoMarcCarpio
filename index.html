Manage, store, and distribute sensitive data with OpenBao

OpenBao is an open source, community-driven secrets manager and fork of Vault managed by the Linux Foundation's OpenSSF.

What is OpenBao? Try it out!

Use cases

🔐

Secure Secret Storage

Arbitrary key/value secrets can be stored in OpenBao. OpenBao encrypts these secrets prior to writing them to persistent storage, so gaining access to the raw storage is not enough to access your secrets.

⚡

Dynamic Secrets

OpenBao can generate secrets on-demand for some systems, such as Kubernetes or SQL databases. After creating these dynamic secrets, OpenBao will also automatically revoke them after the lease is up.

🗝️

Data Encryption

OpenBao provides encryption as a service with centralized key management to simplify encrypting data in transit and stored across clouds and datacenters.

🪪

Identity based access

Organizations need a way to manage identity sprawl across clouds, services and systems. OpenBao uses a unified ACL system to broker access to systems and secrets and merges identities across providers.

⏳

Leasing and Renewal

All secrets in OpenBao have a lease associated with them. At the end of the lease, OpenBao will automatically revoke that secret. Clients can renew leases via built-in renew APIs.

🚫

Revocation

OpenBao has built-in support for secret revocation. It can revoke single secrets, or a tree of secrets, for example all secrets read by a specific user, or all secrets of a particular type.

Frequently Asked Questions

What is OpenBao's mission statement?

OpenBao exists to maintain and improve a software solution to manage, store, and distribute sensitive data including secrets, certificates, and keys. The OpenBao community will provide this software under an OSI-approved open-source license, led by a community run under open governance principles.

What is the status of the fork?

OpenBao is an open source, community-driven fork of HashiCorp Vault, managed by the Linux Foundation. See the Community page to follow its progress.

Which version of HashiCorp Vault are you planning to fork from?

OpenBao is based on the last version of Vault released under the MPL 2.0 license. Check the official documentation for the exact details.

How do I get involved?

The best way is to contribute: open issues, join the discussion and send code through the project's GitHub repository. See the Community page.

Will the existing MPL 2.0 licensed code be migrated to another license?

No. The OpenBao project keeps the existing MPL 2.0 licensed code under its open-source license. Check the official project policies for details.

Contributing

The best way to support the OpenBao project is to contribute. The contribution guide explains recommended practices, how to submit issues, how to get involved in the discussion and much more.
